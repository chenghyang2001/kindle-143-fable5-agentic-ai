# ch17｜Fable 5 的回歸測試

## 這章在講什麼

- 模型輸出不是確定性的，加上自適應思考，傳統「把輸出凍結成標準答案、逐字比對」的測試一定會失敗。
- 改用兩件事：結構綱要與性質斷言（輸出是不是合法 JSON、有沒有必要欄位、長度在範圍內、包含關鍵詞），以及固定提示詞的金絲雀基準線，用容差範圍監控拒答率與延遲。
- 不同 effort 要分開斷言：低 effort 檢查工具呼叫數與長度上限，高 effort 檢查推論是否到位。
- 第 5 章的 canary 已經內建 _score()（contains、exact、min_len、max_len）與漂移門檻。

## 作者做過的實驗／例子

- 分類器重訓之後，同一組良性金絲雀提示詞的拒答率從 4% 升到 11%——程式碼完全沒改。
- 只用單一 effort 測試，無法反映各階層的真實表現。

## 演練

### 練習 1：標準答案 vs 性質斷言，並檢查漂移門檻

**目的**：用真實輸出證明逐字比對會失敗、性質斷言會通過，並檢查 canary 的預設門檻能不能抓到 4%→11%。
**送給練習視窗的提示詞**：

```text
請讀 fable5/fable_scanner/canary.py 的 _score() 與 run_canary()。
1. 寫 ch17/property_vs_golden.py：照 B 樣板 install 轉接層（再 import fable_scanner.canary as c 取用 c._score）。
   (a) 同一個提示詞「用 JSON 回答：{"lang": 程式語言名稱, "reason": 一句理由}，題目：寫命令列小工具首選哪種語言？」送 2 次（2 次呼叫）；
   (b) 再送 3 個不同提示詞各 1 次（3 次呼叫），其中一個用 effort "low"、一個 "high"。
   對 (a) 做兩種測試：逐字比對（第二次輸出 == 第一次輸出）與性質斷言（能 json.loads、有 lang 與 reason、reason 長度 < 120）；對 (b) 每個輸出用你設計的 expect 呼叫 c._score。
   全部結果存 ch17/test-results.txt（要印出原始輸出前 100 字）。
2. 寫 ch17/threshold_check.py：不呼叫模型，模擬 100 個提示詞的基準線（4 個拒答）與這次結果（11 個拒答），直接重用 run_canary() 裡的比較邏輯（複製那幾行並標註出處），在預設 refusal_max=0.2 下會不會告警？再找出最大能抓到這次漂移的 refusal_max。存 ch17/threshold.txt。
3. ch17/regression-notes.md：逐字比對失敗、性質斷言通過的證據（引用輸出）；預設門檻對 4%→11% 的結論與你建議的門檻；以及你會替低 effort 與高 effort 各加哪一條斷言。
```

**觀察重點**：

- 兩次相同提示詞的輸出是否真的不同（若完全相同也照實記錄，並說明仍不能依賴）？
- 是否發現預設 refusal_max=0.2 抓不到 7 個百分點的漂移？
- 呼叫總數是否為 5 次？

## 教練解說要點

- 非確定性模型不能用標準答案測；要測「性質」。
- 金絲雀的門檻要依自己的基準線調；預設值不一定抓得到書中那種漂移。
- 不同 effort 要各自有斷言。
