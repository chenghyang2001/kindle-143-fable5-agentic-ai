# ch11｜自適應思考與跨模型重放陷阱

## 這章在講什麼

- Fable 5 的思考永遠開著，模型自己決定想多深；思考區塊會出現在回應裡（預設內容省略）。
- 重放對話歷史時有兩條方向相反的規則：
  - 同一個模型繼續對話：思考區塊要原封不動保留，連空的也不能刪、不能改。
  - 轉給另一個模型（例如備援的 Opus）：思考區塊要整個剝掉，否則就是白付輸入 token。
- 日誌清洗程式常常「好心」過濾空白區塊，結果在同模型的下一輪造成 400 驗證失敗。
- 這章在書附 repo 沒有獨立資料夾，但第 7 章的 migration_linter 已經會警告「assistant 帶著思考區塊」。

## 作者做過的實驗／例子

- 同模型連續對話時，自行過濾了空白思考區塊，下一次呼叫直接 400。
- 轉交備援時忘了剝思考區塊：不報錯，但帳單多了一截。
- 串流時思考內容省略，前端會靜默數秒，介面要提示「思考中」。

## 演練

### 練習 1：寫一個重放輔助函式並用 linter 驗證

**目的**：把兩條相反的規則寫成程式與測試，並用第 7 章的 linter 交叉驗證。不需要呼叫模型。
**送給練習視窗的提示詞**：

```text
請讀 fable5/migration/migration_linter.py 裡檢查 assistant 思考區塊的那段。
1. 寫 ch11/replay.py：函式 prepare_history(messages, source_model, target_model)：
   - source 與 target 相同：回傳的歷史和輸入逐位元組相同（用 json.dumps 比對），包括空的 thinking 區塊與 redacted_thinking；
   - 不同：移除所有 assistant 訊息裡 type 為 thinking 或 redacted_thinking 的區塊，其餘不動；若某則 assistant 訊息因此變成空的，保留一個說明性的 text 區塊並在註解寫為什麼。
   - 不可修改傳入的原物件（回傳深拷貝）。
2. 在 ch11/history.json 自造一段 4 輪對話（含一個有內容的 thinking、一個空 thinking、一個 redacted_thinking、一個 tool_use 與 tool_result）。
3. 在 replay.py 底部 if __name__ == "__main__": 寫至少 5 個 assert（同模型完全相同、跨模型沒有思考區塊、原物件未被改、tool_use／tool_result 保留、空訊息處理），另外再寫一個「好心清洗」的錯誤版本示範它破壞了同模型規則。
4. 把跨模型處理前與處理後的歷史各包成一個請求本體（model 填目標模型），用 migration_linter 的 lint() 各跑一次，確認處理後那條 messages 警告消失。
執行並把所有輸出存 ch11/replay-results.txt，再寫 ch11/replay-notes.md 說明兩條規則為什麼方向相反。
```

**觀察重點**：

- 同模型分支是否真的位元組相同（連空思考區塊都在）？
- linter 前後對照是否顯示警告消失？
- 是否處理了「不修改原物件」？

## 教練解說要點

- 同模型：思考區塊一個都不能動；跨模型：一個都不能留。兩條規則方向相反，最容易寫錯。
- 「好心清洗」是最常見的 400 來源。
- 第 7 章的 linter 可以當這個輔助函式的驗證者：工具彼此互相驗證。
