# ch18｜治理代理部署：CISO 控制地圖

## 這章在講什麼

- 全書的機制收斂成一張控制地圖，五大領域：資料、可用性、成本、完整性、保證。
- 用 10 個不可覆寫的布林條件組成上線閘門，取代主觀的成熟度評分：任何一項是 false，就不准碰正式流量。這 10 項涵蓋模型版本記錄、資料保留已簽核、拒答路徑已接、備援盲區已補、Mythos 範圍封包、Mythos 產出管控、記憶檢疫、MCP 最小權限、注入邊界、驗證者在線。
- 每一項都能對回前面某一章的工具：scope_gate、migration_linter、fable_scanner、startup_scan、工具描述掃描、驗證子代理。
- 這章當全書的收尾：把前面的練習產出當成證據，真的跑一次上線判定。

## 作者做過的實驗／例子

- 零資料保留的問題要在架構簽核前確認，否則第一個請求就被擋，事後改程式救不回來。
- 從 Fable 降到 Opus 備援時，MCP 工具權限不會自動縮小，若沒做最小權限，備援模型會在過大的權限下行動。

## 演練

### 練習 1：上線稽核＋10 項硬閘門

**目的**：讓模型做一次上線前稽核，再用不靠模型的 10 項布林閘門做最終判定，證據取自前面各章的產出。
**送給練習視窗的提示詞**：

```text
1. 真的跑上線稽核專案（3 次模型呼叫，約 1～2 分鐘）：K143_CLI_LOG=ch18/calls.jsonl PYTHONUTF8=1 python run_with_cli.py fable5/projects/07_ship_readiness/ship_audit.py，輸出存 ch18/ship-audit.txt。
2. 寫 ch18/deployment.json：描述「把 projects/07 的客服代理上線」的部署清單，欄位對應 10 個閘門（model_variant_documented、retention_resolved、fable_refusal_path_wired、fallback_gap_handled、mythos_scope_packet_required、mythos_artifact_controls_on、memory_gate_on、mcp_least_privilege、injection_boundary_set、verifier_running），每個欄位附 evidence：指向本演練裡真的存在的檔案（例如 ch07/lint-after.txt、ch03/scan-output.txt、ch14/scan.txt、ch06/gate-results.txt）或寫 "none"。不存在的證據一律填 none，不可假造。
3. 寫 ch18/go_no_go.py：讀 deployment.json，對每一項判定：值必須是 true「而且」evidence 指向的檔案真的存在且非空，否則視為 false；不適用 Mythos 的兩項，只有在 model 是 claude-fable-5 時才可標為 not_applicable。印出 10 項結果表與最終 GO／NO-GO，並以 exit code 0／1 結束。執行並存 ch18/gate-result.txt。
4. ch18/ciso-map.md：五大領域各對應哪幾個閘門、哪一章的工具；把 ship-audit.txt 裡模型找到的問題（例如退款工具沒有速率限制）對到它會讓哪個閘門變 false；最後一段寫：如果要讓結果變成 GO，還缺哪些證據（列清單，不要真的去補）。
```

**觀察重點**：

- evidence 是否全部指向真的存在的檔案，缺的就老實寫 none？
- go_no_go.py 是否真的檢查檔案存在，而不是只看 true／false？
- 模型稽核的發現有沒有對回具體閘門？

## 教練解說要點

- 上線決策用布林閘門，不用分數：任何一項 false 就是 NO-GO。
- 閘門要看證據，不是看宣稱——這正是第 6 章「證據綁定進度」的組織版。
- 全書工具在這裡匯流：每個閘門都有一支前面寫過或跑過的程式可以當證據。
- 演練得到 NO-GO 是正常的；重點是知道還缺什麼。
