# ch10｜Effort 旋鈕就是成本旋鈕

## 這章在講什麼

- Fable 5 用 output_config.effort 控制深度，有五級：low、medium、high、xhigh、max；不設就是 high。
- effort 影響「所有」輸出 token：文字、工具呼叫參數、思考。調低不只回答變短，工具呼叫也變少。它是行為訊號，不是硬上限。
- 作者主張：把整個機隊的成本政策寫成一個函式——依任務類型路由 effort，例行工作跑便宜，只有對能力敏感的任務才付 xhigh 的錢。
- 範例 effort_router.py 的 effort_for() 就是那一個函式；skills/effort-router 則是讓代理自己挑 effort 的技能版。

## 作者做過的實驗／例子

- 沒設 effort 的機隊全跑在 high，連單純的格式擷取、分類都在燒思考 token。
- 降 effort 會同時縮短回答、減少推論深度與工具呼叫次數。
- 範例把審查者（grader）設 low、執行 medium、規劃與綜合 xhigh。

## 演練

### 練習 1：同一任務不同 effort，量真實的輸出 token

**目的**：用真實呼叫看到 effort 對輸出 token 的影響，並把自己的工作寫進路由政策。
**送給練習視窗的提示詞**：

```text
請讀 fable5/effort/effort_router.py 與 fable5/skills/effort-router/SKILL.md。注意：不要直接執行 effort_router.py（它的 main 會一次跑三個任務），改用匯入。
1. 寫 ch10/effort_run.py：照 B 樣板 install 轉接層，import effort.effort_router as er。
   (a) 用 er.run() 跑 3 個任務：kind="classify"（一張工單是 bug 還是 feature）、kind="summarize"（一段部署失敗紀錄）、kind="audit"（替一個能讀工單又能部署的代理做簡短威脅評估，請在 prompt 要求 10 行以內）。3 次呼叫。
   (b) 再用 claude_cli_client.Anthropic().messages.create 把同一個 summarize 提示詞分別用 effort "low" 與 "xhigh" 各跑一次。2 次呼叫。
   印出每次的 kind、effort、output_tokens，並存 ch10/effort-results.txt。
2. 寫 ch10/my_router.py：複製 effort_for() 到這裡改成你的版本，加入至少 3 種你在這場演練中實際會遇到的任務類型（例如 grade、lint-explain、write-report），每種附一行為什麼選這個 effort；底部用 assert 測每種類型的回傳值，執行存 ch10/my-router.txt。
3. ch10/effort-notes.md：low 與 xhigh 的 output_tokens 差幾倍；用 README 的 Fable 輸出單價算出這兩次的輸出成本差（標明只是本次樣本）；說明為什麼「effort 不是硬上限」，以及轉接層用 claude -p --effort 傳遞，結果可能和直接打 API 不完全相同。
```

**觀察重點**：

- 是否避開執行 main，只做 5 次呼叫？
- low 與 xhigh 的 token 差異是否來自真實 usage？若差異很小也要照實說。
- 自訂路由的 assert 是否全過、理由是否具體？

## 教練解說要點

- effort 是機隊的成本政策：一個函式、一處修改。
- 降 effort 連工具呼叫都會變少，所以不只是「回答短一點」。
- 審查者跑 low、執行 medium、規劃 xhigh，是最常見的起點；再用真實 token 數調整。
