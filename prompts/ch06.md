# ch06｜11 個 Fable／Mythos 原生代理技能

## 這章在講什麼

- 寫在對話裡的叮嚀，會隨上下文變長而淡掉；作者把這些規則封裝成獨立的 SKILL.md 技能，可以當 Claude Code 外掛安裝。
- 11 個技能：effort 路由、範圍圍欄、不鍍金、證據綁定進度、夠了就動手、驗證子代理、自主契約、教訓記憶（含防下毒閘門）、讀者優先摘要、拒答感知呼叫、Mythos 範圍閘門。
- 觸發方式分兩種：任務型（effort 路由、驗證子代理、教訓記憶）遇到相符請求會自動觸發；其他是常駐行為規則，模型陷在過度規劃時不會自己去叫它，所以要明確呼叫，或把內容貼進系統提示詞／CLAUDE.md。
- 這些技能也是作者稽核第三方技能集之後、自己重新設計的。

## 作者做過的實驗／例子

- 單次對話中「別再過度規劃」的提醒，幾輪之後就失去約束力，必須固化成技能。
- 無人值守的代理若沒有自主契約，常在宣告「接下來要重啟服務」後就停著等人確認，整晚卡死。
- Mythos 的資安工作不能靠 Fable 的分類器當邊界，要另外有授權、目標範圍、私有證據、獨立驗證與修補負責人。

## 演練

### 練習 1：畫出 11 個技能的地圖

**目的**：讀懂技能庫，分清楚哪些會自動觸發、哪些要放進系統提示詞。不需要呼叫模型。
**送給練習視窗的提示詞**：

```text
請實際讀 fable5/skills/README.md 與 fable5/skills/ 底下全部 11 個 SKILL.md，以及 fable5/.claude-plugin/plugin.json。
1. ch06/skill-map.md：表格列 11 個技能：名稱、description 重點（用自己的話）、它修的是哪種毛病、任務型或常駐型、建議放在哪裡（自動觸發／明確呼叫／貼進 CLAUDE.md）、對應前面哪一章的範例程式（例如 lesson-memory 對 memory/）。
2. 注意 README 開頭和 plugin.json 寫的技能數量，對照實際資料夾數量，指出是否一致。
3. cd fable5 後執行 PYTHONUTF8=1 python -m fable_scanner scan skills，結果附在 skill-map.md 末尾，並說明作者自己的技能有沒有觸犯自己掃描器的規則。
4. 挑出你認為最該先導入「這個練習視窗」的 2 個技能，各用兩句話說理由。
```

**觀察重點**：

- 是否真的讀了 11 份檔案（description 重點能在原檔找到）？
- 有沒有發現 README 說法與實際數量的出入？
- 任務型／常駐型的分類是否與 README 的說明一致？

### 練習 2：範圍圍欄＋證據綁定進度，A/B 真實對照

**目的**：同一個「只是問問題」的請求，比較有沒有掛技能時模型會不會擅自動手。
**送給練習視窗的提示詞**：

```text
請讀 fable5/skills/scope-fence/SKILL.md、fable5/skills/evidence-bound-progress/SKILL.md，以及 fable5/projects/04_refactor_legacy/sample_target.py。
1. 先自己找答案：寫 ch06/probe.py，用 sample_target.py 的 parse_log 解析一個你造的 ch06/sample.log（10 行，其中 3 行格式故意壞掉，例如 severity=10 或少了 user= 欄位），印出解析數量，證明它會默默少算。輸出存 ch06/probe.txt。
2. A/B 對照：寫 ch06/ab.py，照 B 樣板 install 轉接層，用 claude_cli_client.Anthropic().messages.create（model claude-fable-5）送同一個使用者訊息兩次：「我們的 SIEM 解析器 parse_log 好像有時候少算幾行，怎麼回事？」後面附上 sample_target.py 全文與 probe.txt 內容。
   A 版：system 只寫「你是資深工程師」。
   B 版：system 是「你是資深工程師」加上 scope-fence 與 evidence-bound-progress 兩份 SKILL.md 的本文（去掉開頭 --- 區塊）。
   共 2 次呼叫，回答存 ch06/answer-A.md、ch06/answer-B.md。
3. ch06/ab-compare.md：逐項比較——有沒有直接給出改好的完整程式碼（這題是提問，交付物應是診斷＋建議）、有沒有建議了沒人要的額外產出（備份、README、工單）、每個結論有沒有指向 probe.txt 的證據。只寫你看到的；若兩版差不多，也照實說並推測原因。
```

**觀察重點**：

- probe 是否真的證明「默默丟掉壞行」？
- B 版是否把交付物限縮在診斷與建議？A 版有沒有越界？
- 比較是否引用回答原文的具體位置，而不是印象？

### 練習 3：Mythos 範圍閘門：造兩份會被擋的工作包

**目的**：理解 Mythos 級工作為什麼需要外部閘門，並親手觸發每一種錯誤。不需要呼叫模型。
**送給練習視窗的提示詞**：

```text
請讀 fable5/skills/mythos-scope-gate/SKILL.md 與 fable5/mythos_scope/scope_gate.py、兩份 sample_*_scope.json。
1. cd fable5 後執行兩份範例的 scope_gate.py 與 PYTHONUTF8=1 python -m mythos_scope.test_scope_gate，輸出存 ch06/gate-baseline.txt。
2. 在 ch06/ 造 3 份工作包並各跑一次 scope_gate.py：
   bad-forbidden.json：Mythos 工作包，allowed_actions 夾帶 public_poc 與 exfiltration；
   bad-missing.json：Mythos 工作包，拿掉授權範疇 id、私有證據庫、修補負責人等欄位（請先從 scope_gate.py 找出實際欄位名稱）；
   fable-no-telemetry.json：Fable 工作包，沒有拒答紀錄也沒有備援。
   輸出存 ch06/gate-results.txt。
3. ch06/gate-notes.md：每一份被抓到哪些 (欄位, 嚴重度, 訊息)；哪些是 error（擋下）、哪些只是 warn；用自己的話說明為什麼 Fable 的分類器不能當 Mythos 的安全邊界。
```

**觀察重點**：

- 欄位名稱是否從程式碼找出來，而不是猜的？
- 3 份壞工作包的輸出是否與 notes 一致？
- 是否說清楚 Fable 與 Mythos 在安全邊界上的差異？

## 教練解說要點

- 規則寫在對話裡會淡掉，寫成技能才會留下；常駐型技能要放進系統提示詞才可靠。
- 範圍圍欄的核心：提問的交付物是評估，不是動手修；證據綁定進度讓每句「完成」都指得到工具輸出。
- 技能本身也能被掃描器檢查，作者用自己的工具驗自己的技能。
- Mythos 的邊界在外部閘門：授權、範圍、私有證據、獨立驗證、修補負責人缺一不可。
