# 第 1 章 練習 1：用五個模組改寫舊提示詞，並讓模型真的回答一次

## 產出檔案

| 檔案 | 內容 |
| --- | --- |
| `ch01/system_prompt.md` | Harness 式系統提示詞，含邊界、接地進度、自主性、白話摘要、上下文平靜五小節 |
| `ch01/scan-compare.md` | 舊版與新版的 fable_scanner 完整輸出，加上規則代碼消失對照表 |
| `ch01/try_prompt.py` | 用轉接層送同一任務兩次（舊版／新版 system） |
| `ch01/answer-old.md`、`ch01/answer-new.md` | 兩份模型回答 |
| `ch01/compare.md` | 兩份回答比較 |

## 1. 新版系統提示詞

五個小節各 1～3 句，開頭用一段話說明情境與目的（讓 build 恢復、改動最小），取代舊版 12 條「Improve X」清單。

## 2. 掃描結果

- 舊版 `bad_prompt.md`：5 個發現、2 個 error（OT-01、RX-01、OM-01、OT-02、FS-01），exit code 1。
- 新版 `system_prompt.md`：0 個發現，exit code 0。
- 每個規則的處理方式：IMPORTANT 框改平實句子（OT-01）、不要求輸出推理過程（RX-01）、清單改成一段意圖說明（OM-01）、不用「YOU MUST」喊叫（OT-02）、拿掉剩餘 token 數字並要求不提剩餘空間（FS-01）。

## 3. 真的送一次

`PYTHONUTF8=1 python ch01/try_prompt.py` 執行成功，`claude_cli_client.calls_made()` 回報 2 次。

- 舊版回答只有 52 字元：「我先逐步排查」＋「步驟 1：確認工作目錄裡有什麼」就結束，沒有任何結論。
- 新版回答 793 字元：分成「已確認的事實」（工作目錄是空的，實際列目錄確認）、「推測（尚未驗證）」（PyYAML 沒列進依賴清單等三個原因，最小修正是加一行 PyYAML）、「我需要的資訊」，並說修改前會先確認。

## 4. 比較結論

- 直接宣稱改了檔案或已修好：兩份都沒有出現。
- 先評估再提建議：只有新版做到；舊版沒有出現任何評估或建議。
- 自創縮寫：兩份都沒有出現。
- 冗長逐步敘述：舊版有逐步敘述的開頭但隨即停止；新版沒有出現。

## 限制

- 轉接層在空的暫存目錄執行 `claude -p`，沒有真實專案可修，比較的是回答的態度與結構。
- 各只送 1 次，舊版提早停住可能有隨機成分。
- 轉接層會忽略 `max_tokens`，沒有伺服器端備援，也不回傳拒答類別。
