# SOC 分流迴圈拆解：fable5/agentic_soc/triage_loop.py

## 六個零件

| 零件 | 位置（函式／行號） | 怎麼運作（我的話） |
| --- | --- | --- |
| 觸發 | `main()` 第 90～93 行 | 從命令列參數拿 JSONL 檔（預設 `sample_alerts.jsonl`），一行一筆告警，逐行 `json.loads` 後進入這一輪。正式環境會換成 SIEM webhook（docstring 第 4 行）。 |
| 規則 | `classify()` 第 52～58 行的提示詞；第 23 行 `VERDICTS`；第 63～64 行解析 | 規定只能回三種判斷之一、第一行寫判斷、引用告警欄位、把告警內容當成攻擊者寫的不可信輸入。解析時第一個字不在三選一裡，就一律當成 `escalate`（寧可升級也不放過）。 |
| 執行者 | `classify()` 第 51～64 行，經 `ask()` 第 28～39 行 | 用 medium effort 呼叫 Fable 5，提示詞裡帶過去的 lessons 摘要和完整告警 JSON。拒答時回 `(None, "refusal")`。 |
| 驗證者 | `verify()` 第 67～76 行 | 全新的一次呼叫（low effort），只給原始告警和判斷結果，不給執行者的理由。第一行以 `AGREE` 開頭才算同意，空回應或拒答都算不同意。 |
| 記憶 | `lessons_digest()` 第 42～48 行（讀）、`distill()` 第 79～86 行（寫）、第 100 行的閘門 | 讀：每個 lesson 檔只取第一行，串成摘要給下一次分類。寫：每筆告警一檔，檔名是 `規則-告警ID.md`，內容一行「規則：verified 判斷（evidence: alert ID）」。只有驗證者同意時，第 100 行才會呼叫 distill。 |
| 停止條件 | `main()` 第 95～97、105～107、108 行 | 三種：執行者拒答就停並請人接手；驗證者連續 3 次不同意就暫停；佇列跑完就停。驗證者同意一次，連續不同意的計數就歸零（第 99 行）。 |

## templates 版和程式版不一樣的地方

| 項目 | templates/alert-triage-loop.md | triage_loop.py |
| --- | --- | --- |
| 時間限制 | 每筆告警 10 分鐘內完成分流 | 沒有任何時間限制或逾時檢查（只有轉接層自己的 180 秒逾時） |
| 豐富化（enrich） | 每輪「pull → enrich → classify」 | 沒有 enrich 步驟，只把原始 JSON 丟給模型 |
| 信心門檻 | 中等以上信心一律升級給人 | 沒有信心分數；只有「解析不到判斷」與「驗證者不同意」時才升級 |
| 證據 | 判斷要附證據 | 只要求理由中引用欄位，`detail` 文字沒有存下來也沒印出 |
| 記憶來源 | 只從已結案的案件寫 lesson | 以「驗證者同意」代替「已結案」 |
| 停止：預算 | 輪次額度用完也要停 | 沒有輪次預算；只有佇列空、連續 3 次不同意、拒答 |
| 不同意時 | 暫停迴圈並呼叫分析師 | 印出 `[stop]` 後 return，沒有真的通知人 |
| 邊界 | 對 SIEM／TIP 唯讀，不做隔離動作 | 本來就沒有任何寫外部系統的程式，唯讀靠「沒寫」達成（docstring 第 10～11 行） |
| 拒答 | 提醒要接上 Opus 4.8 伺服器端備援 | 有帶 `betas` 與 `fallbacks`（第 20～21、33～34 行）；拒答還是會直接停 |
