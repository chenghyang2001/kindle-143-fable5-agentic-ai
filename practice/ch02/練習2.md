## 重點

- **(a) effort**：拆題 xhigh（規劃、只跑一次、錯了整輪偏掉）；搜尋 medium（執行、每角度一次）；投票 low（評分、數量最多、任務窄，用三票換可靠度）。
- **(b) 推翻設計**：角色寫成 adversarial、任務是 Try to REFUTE、自己用 web_search 找證據、只給主張與來源不給搜尋者敘述、三票是互不相見的全新上下文、第一個字強制 REFUTED／SUPPORTED、2/3 推翻才淘汰。投票者 1 自己點出「frontmatter 欄位其實是選填」，顯示它確實在找漏洞。
- **(c) 轉接層差別**：task_budget 和 max_uses 被忽略（搜尋沒有上限）、伺服器端 web_search 換成 Claude Code WebSearch、max_tokens 被忽略、沒有 Opus 4.8 備援、看不到拒答類別、底層是 Claude Code 代理而不是原生 API。
- **(d) 可信度**：我覺得可信，跟這台機器上 skills 的放法一致；只有「必須」說得太滿（frontmatter 欄位是選填）。來源網址三票都引用了，看起來存在，但我沒有親自打開確認；而且三票引用的都是主張附的同一個來源，不算獨立證據。
