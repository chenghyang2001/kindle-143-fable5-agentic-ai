## 1. 修之前

原始範例：6 個 finding（error：temperature、top_p、thinking.budget_tokens；warn：messages 的 thinking 區塊、fallbacks；info：output_config.effort），3 個會在 Fable 5 回 400，exit 1。test_migration_linter 3/3 通過。

## 2. 修之後

刪掉 temperature／top_p、整個 thinking 欄位，以及 assistant 回合的 thinking 區塊；加上 `fallbacks: [{model: claude-opus-4-8}]` 與 `output_config.effort: medium`（摘要屬於例行轉換）。model 原本就是 claude-fable-5，保留。linter 結果：`clean: this request is already Fable-5 valid`，exit 0，0 error、0 warn、0 info。

## 3. CI 閘門

| 檔案 | 結果 |
| --- | --- |
| 01-fixed.json | PASS |
| 02-original-opus.json | FAIL：temperature、top_p、thinking.budget_tokens |
| 03-top-k-only.json | FAIL：top_k |
| 04-thinking-disabled.json | FAIL：thinking |

4 份有 3 份有 error，**exit code 1**。另外驗證了邊界：空資料夾 exit 2、壞 JSON 也算 error（exit 1），不會偷偷通過。閘門只用 error 擋，warn 只列出不擋。

## 4. 後果與缺口

- 取樣參數、thinking disabled、budget_tokens → **400**。
- 沒有 fallbacks → 拒答時 HTTP 200 空內容，**卡死**。
- assistant 帶著思考區塊 → 換模型或走備援時出問題，寫進歷史紀錄後**日後難改**。
- 沒設 effort → 預設 high，簡單工作**白花錢**，日後要整個機隊調整也得一份一份改（**日後難改**）。

**linter 沒查、但該查的：model 有沒有真的改。** 實測 `{"model": "claude-opus-4-8", …}` 的 lint 結果是空清單，會被報成「已經是 Fable 5 合法請求」；fallbacks 的 warn 也只在 model 是 fable 時才檢查。建議遷移模式下，model 不在目標清單就報 error。另外，`thinking: {type: enabled}` 沒帶 budget 不會被抓，fallbacks 所需的 beta header 也沒有檢查。

`fable5/` 未修改；`migration/__pycache__` 已刪除。
