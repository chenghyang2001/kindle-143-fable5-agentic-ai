## 測試

- **FakeClient**：`client.beta.messages.create(**kw)` 用深拷貝把每次的 kw 存進 `calls`，並照預先排好的劇本依序回傳 SimpleNamespace；拒答的回應帶 `stop_details.fallback_credit_token` 與 `fallback_has_prefill_claim`。
- (a) 第一次成功：只呼叫 1 次，沒有 fallback_credit ✅
- (b) 拒答＋有 token：第二次只換 model（fable → opus）並加上 `fallback_credit={token, has_prefill_claim: True}`，其餘欄位的值與順序都一樣；原始 params 沒被改 ✅
- (c) 拒答＋沒有 token：仍然重試到 Opus，但沒有 credit ✅
- (d) served_by_sticky：只有 fallback_message → True；兩者都有 → False（另外驗證了只有 message、iterations=None 都是 False）✅
- (e) `body_matches(first, retry)`：忽略 model 與 fallback_credit 後比較本體。正確重試 → True；「好心」刪掉空字串的 text 區塊 → **False** ✅

body_matches 比的是 dict，只改欄位順序時仍回 True；伺服器比對的是收到的請求本體，所以 HTTP 層如果會重新序列化，就要改成比對最終位元組。

## 成本例子（全部是假設）

系統提示詞 50,000 token（已快取）、新訊息 500 token、輸出 800 token；Fable $10／$50（README）、Opus $5／$25（README 沒寫，取自 monitor.py）、寫快取 1.25 倍、讀快取 0.1 倍。

| 重試到 Opus | 系統提示詞 | 合計 |
| --- | --- | --- |
| 沒帶 token（重新寫快取） | 50,000 × 1.25 × $5/M ＝ $0.3125 | **$0.3350** |
| 有帶 token（當成讀快取） | 50,000 × 0.1 × $5/M ＝ $0.0250 | **$0.0475** |

每次差 **$0.2875**（約 7 倍）；每月 6,000 次拒答就是約 $1,725。差額幾乎全來自長的系統提示詞。

## 轉接層為什麼無法示範

claude -p 不回傳 stop_details，拿不到 credit token；`betas` 與 `fallback_credit` 被當成不支援的參數忽略；每次呼叫都是新的 Claude Code session，包著它自己的系統提示詞與快取，請求本體看不到也控制不了；走 Max 訂閱，沒有逐 token 帳單可以比較寫入與讀取快取的價差。
