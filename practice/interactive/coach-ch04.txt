K143 第 4 章互動演練：昂貴規劃，廉價建置（教練稿）

【第 1 步：主角登場：一個迴圈、四段、兩種價位】
這一步我們打開本章的主角，job packet 這支小程式，它只有四個函式。畫面會先印出原文說明，接著是一張對照表，列出每一段用哪個模型、預設的思考力度是多少。你會看到準備和執行這兩段交給便宜的 Sonnet，規劃稽核和驗證這兩段才用貴的 Fable 5。這一步完全不呼叫模型，馬上就有結果。目的，是先看清楚貴的模型只花在判斷最密的那兩段。

【第 2 步：十個專案各走了哪幾段】
接著我們掃過書附的十個週末專案，看每個專案從 job packet 匯入了哪幾段。畫面會出現一張十列的表，打勾代表有用到那一段。你會發現規劃稽核那一欄十個專案全部打勾，但成本儀表板連準備那一段都沒有用。這一步一樣不呼叫模型。目的，是證明十個專案其實是同一個迴圈換資料，而且不是每段都非用模型不可。

【第 3 步：一句話測試：算術交給 Python，順便做答案卷】
這一步用純 Python 把一週的用量紀錄加總，算出每個模型花了多少錢。接著把原本跑在 Fable 5 上的每一筆，換算成改用 Haiku 會是多少錢，並標出哪些是一句話就能交代的小任務。你會看到 Fable 這週的花費，大部分其實來自兩個真正需要判斷的任務，小任務改路由一個月只省幾分錢。這份結果會存成答案卷，下一步拿來抽驗模型。目的，是體會沒有分支、沒有判斷的算術，根本不必花模型的錢。

【第 4 步：跑成本儀表板：Fable 設計路由政策、Sonnet 寫報告】
這一步真的跑成本儀表板，會呼叫模型兩次，大約要等一到三分鐘。第一次由 Fable 5 用高力度設計路由政策，第二次由 Sonnet 根據政策寫執行報告，每次呼叫都會記進紀錄檔。跑完之後，畫面會列出輸出裡出現過的金額，再接著印出上一步的答案卷。請你拿模型說的每月節省去對照答案卷，很可能對不上，而對不上正好說明為什麼下一步要看呼叫紀錄。目的，是親眼看到貴的和便宜的模型各被叫一次，並且用答案卷抽驗模型算的數字。

【第 5 步：用呼叫紀錄驗證，不聽模型自己說】
這一步不呼叫模型，而是讀上一步留下的紀錄檔，一筆一筆列出每次呼叫要求哪個模型、實際是哪個模型、用了多少 token。接著交給書附的監控工具算出總次數、拒答次數和各模型的花費。最後我們對照兩張價目表，會發現 Sonnet 在兩處的價格對不上，而且成本儀表板用的優惠價早就過期了。要注意，這次走的是 Claude Code 轉接層，紀錄裡的輸入 token 只是命令列回報的值，可能只顯示個位數，換算出來的金額也不是真的帳單；真實部署接上 API 時，這份紀錄才會是準的。目的，是建立一個習慣：成本要從呼叫紀錄追，不要相信模型報告裡自己算的金額。

【第 6 步：MCP 連接器稽核，先用四條規則判】
這一步換到 MCP 連接器稽核這個專案，先不用模型，只寫四條規則：權限太大、沒有驗證、太久沒用、金鑰放在環境變數。畫面會列出六個連接器的分數和命中了哪幾條規則，舊的 Jira 連接器會拿到最高分。結果會存成一個檔案，等一下拿來對照。目的，是說明能用規則判斷的事，先用程式判，省下模型的錢留給真正需要判斷的地方。

【第 7 步：跑 MCP 稽核：模型多看出什麼】
這一步真的跑 MCP 稽核，會呼叫模型三次，大約要等兩到四分鐘。Sonnet 先整理連接器清單，Fable 5 用高力度做排名和整併計畫，最後 Sonnet 寫出要撤銷、要縮權限、要定期審查的清單。跑完會印出呼叫紀錄的統計，再把上一步的規則排名並排在最後。請你看看模型多講出了哪些規則抓不到的判斷；另外，資安題目容易被資安分類器擋下，這次走轉接層看不到備援，真實部署要先接好。目的，是分辨模型的貢獻裡，哪些是真正的判斷，哪些只是重複了規則早就知道的事。

【第 8 步：總結：昂貴規劃，廉價建置】
最後一步直接印出本章六個重點。一個迴圈套用到十個專案，貴的模型只放在判斷最密的那段，其他交給便宜模型，甚至交給純 Python。錢花在哪要看呼叫紀錄，價目表過期或不一致，報表就會默默算錯。真實部署時，還要先接好備援，並處理模型拒答的情況。目的，是把昂貴規劃、廉價建置這個原則，變成你之後設計代理流程時的第一個檢查項目。
