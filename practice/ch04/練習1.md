## 1～2. 執行與 monitor

週摘要（Python 算）：Fable 7 次 $0.76、Sonnet 3 次 $0.12、Haiku 2 次 $0.00。monitor：總共 2 次、0 次拒答、0 次備援；這次執行本身的費用是 Fable $0.1029＋Sonnet $0.0111。

## 3. 流程

```text
prep（純 Python summarize，無模型）
  → plan_or_audit（claude-fable-5，effort high）   ← 呼叫 1
  → execute（claude-sonnet-5，effort medium 預設）  ← 呼叫 2
  → verify（沒有走）
```

模型名稱是從 log 對照的；effort 沒有寫進 log，是從程式讀的（第 62 行明寫 high；execute 沒傳，所以用 packet.py 的預設 medium）。

**週摘要金額是 Python 算的**（summarize()，在呼叫模型之前就印出來了）；錯路由表格的金額是模型算的。

驗算：模型只拿到加總與 task_type 清單，沒有每筆的 token 數，所以用 Fable 的平均每次 $0.109 估算每一項。

| 任務 | 實際每週省 | 模型說 |
| --- | --- | --- |
| typo_fix → Haiku（500／50 tokens） | $0.0075 − $0.00075 = **$0.00675** | $0.098（高估約 14.5 倍） |
| fix_one_test → Sonnet（700／150 tokens） | $0.0145 − $0.0029 = **$0.0116** | $0.087（高估約 7.5 倍） |

五項實際合計每週省 $0.032，模型說 $0.48，高估約 15 倍：Fable 的錢幾乎都花在 threat_model 和 migration_plan 上，平均值被這兩筆撐大了。模型自己有寫「用平均值」的但書，但 execute 照抄數字再乘以 4，但書就消失了。路由方向對、金額錯。這次跑儀表板本身花了約 $0.114，比實際每週可省的還多。

## 4. 一句話測試

execute 可以降到 Haiku（甚至直接用 Python）：它只是把 Fable 列好的表格排版並乘以 4，沒有分支、也不需要判斷；真正缺的反而是 verify，應該用 Python 從 CSV 重算金額來對照。
