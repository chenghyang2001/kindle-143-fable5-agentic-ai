## 結果

| # | 情境 | 原版 | 修正版 |
| --- | --- | --- | --- |
| 1 | 正常 create → view | ✅ | ✅ |
| 2 | `/memories/../../secret.txt` | ✅ ValueError | ✅ error 字串 |
| 3 | `C:\Windows\win.ini`（view） | ✅ ValueError | ✅ error 字串 |
| 4 | create 10,667 字中文（32,001 bytes） | ✅ 拒絕 | ✅ |
| 5 | str_replace 換成超大字串 | ❌ 寫入，32,003 bytes | ✅ 拒絕 |
| 6 | insert 超大字串 | ❌ 寫入，32,025 bytes | ✅ 拒絕 |

中文字數：32,000 ÷ 3 = 10,666.67，10,666 字（31,998 bytes）還在上限內，10,667 字（32,001 bytes）就超過。

## 發現

- **有效**：路徑逃逸與 rename 逃逸都擋住（先 resolve 再檢查是否在 ROOT 底下）；Windows 絕對路徑也被擋，但那是包含檢查剛好接住，不是刻意設計；create 以 UTF-8 bytes 算上限。
- **繞過**：
  1. str_replace 與 insert 沒有大小檢查，先建小檔再灌內容就能無限長大。
  2. Windows 文字模式把 LF 寫成 CRLF，檢查與磁碟大小不一致，換行多的內容可以超過上限 50%。
- **行為不符預期**：擋下時丟 ValueError 而不是回 tool_result，迴圈沒包 try 就會中斷；`/memoriesX/a` 這種前綴也會被接受；docstring 說有 provenance 要求，但程式沒有實作；delete 不存在的檔也回 deleted，rename 會覆蓋。

## 修法（handler_fixed.py，重跑 8/8）

共用 `_write_capped()` 檢查最終內容、以 bytes 讀寫避免換行膨脹、前綴嚴格比對、`handle()` 把錯誤轉成 `error:` 字串、rename 不覆蓋、insert_line 檢查範圍。provenance 檢查尚未示範。
