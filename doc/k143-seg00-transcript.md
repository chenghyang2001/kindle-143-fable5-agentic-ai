**[14:49]** 那第三個區塊？第三是「自主性」區塊，這跟第一個邊界區塊是互補的。所以大方向要你批准，但你要授權模型自己去做微小的決定？像是變數命名之類的嗎？沒錯。比如這個內部變數該命名為 `userId` 還是 `id`，告訴它自己決定，不要事無巨細都停下來問你，那樣太沒效率了。真的，我不想連這種小事都要我點頭。

**[15:13]** 第四個呢？第四是「白話摘要」區塊【註：原音說「純英文摘要」，應是 plain-English summary 的直譯；書中模組名為「白話摘要」】，這就是為了解決我們剛才說的 Claudish 問題，要求它在最終總結的時候好好講人話、寫出完整的句子。哈哈，拒絕看那些密密麻麻的箭頭縮寫。

**[15:26]** 最後一個呢？最後是「上下文平靜」區塊（原音說「上下文冷靜」），這解決了一個很現實的問題：模型在處理超長任務時會產生上下文焦慮。AI 也會焦慮？會啊。有時候模型看到剩下的空間不多了，會隨意刪減工作來省空間。你要在這個區塊明確告訴它：空間還很多，繼續做，不要慌，不需要為了節省 token 而犧牲品質。

**[15:49]** 這五個區塊真的超級實用耶。這才是真正與 AI 溝通的藝術：不是教它怎麼敲鍵盤，而是設定好遊戲規則和邊界。不過當我們把這套 Harness 寫好，實際把手放在鍵盤上、準備傳送 API 請求給 Fable 5 時，指南說還有幾個隱藏的 API 地雷，和一個全新的魔法旋鈕。這又是什麼情況？

**[16:13]** 這裡談的是 API 層面具體的變更。很多工程師會帶著舊習慣來呼叫新模型，結果就踩雷了。什麼樣的雷？首先，Fable 5 的自適應思考（adaptive thinking）現在是永遠開啟的，如果你在 API 裡面傳送試圖關閉它的指令，你會直接收到一個 400 錯誤。那其他的常見參數呢？以前我們總喜歡去微調像是 temperature，也就是溫度這種參數——用來控制模型創意度還有隨機性的旋鈕——還有 top_p 這些。都不行了？對，如果你試圖設定 temperature 或 top_p，同樣會直接被拒絕。API 的控制表面被官方刻意縮小了，模型現在會自己根據任務上下文判斷需要多少創意。哇，全自動化了。

**[16:57]** 還有其他地雷嗎？另外一個地雷是，如果你的組織基於資安規定設定了零資料保留（zero data retention），所有的 Fable 5 和 Mythos 5 請求都會回傳 400 錯誤，因為這兩個旗艦模型強制要求 30 天的資料保留期來進行安全稽核。了解，所以不要再去亂調溫度，也要注意資料保留政策。

**[17:18]** 那剛剛提到取代這些舊參數的魔法旋鈕是什麼？它叫做 effort，也就是努力值參數。它現在是一個一級的 API 參數，總共分為 low、medium、high、xhigh 到 max 五個等級，預設值是 high。effort 參數，那這有什麼特別的？這裡有一個巨大的反常識認知：對於日常開發工作，千萬不要盲目地把它開到最大的 max。為什麼？既然我都付錢用旗艦模型了，難道不該讓它全力以赴、思考越久越好嗎？

**[17:51]** 因為在日常任務中，開到最大只會讓你花更多錢、等更久的時間。它可能會對一個超級簡單的正規表示式【疑：原辨識為「政策表示式」，依語意推測為「正規表示式」】過度思考 10 分鐘，卻完全得不到更好的結果。就是殺雞用牛刀的意思。沒錯。但最顛覆的一點是，指南特別強調：在 Fable 5 這種頂級模型上，如果你使用 low 或 medium 的 effort 去跑日常任務，它的表現通常能擊敗在舊模型上開到最大 effort 的結果。

**[18:19]** 這裡真的超有趣。所以你的意思是，這就像是讓一個米其林三星大廚隨便幫我炒個蛋，也絕對比我自己看著食譜、滿頭大汗煮一個小時還要好吃，而且以 API 的計價來說居然還更便宜。這個比喻非常貼切。這完全顛覆了我們對預算分配的認知。我一直以為要省錢就是去買便宜的舊模型，然後把 effort 調到爆【疑：原辨識為「抄到爆」】。

**[18:45]** 這引出了一個重要的問題，也是 2026 年 AI 工程師必須具備的核心能力：我們該如何動態調整 effort 這個參數。它不再只是個提升智力的按鈕了【疑：原辨識為「提升至上」】，它是你控制成本和系統延遲的精密閥門。你需要根據 Harness 中不同環節的難易度，動態設定不同的 effort，而不是一招打天下。

**[19:05]** 這真的太精彩了。我們今天從一份實戰工程指南出發，徹底拆解了 2026 年 AI 戰場的真實樣貌。總結來說，現在的贏家絕對不再是那些能在文字框裡寫出最長、最複雜指令的人。沒錯，那個時代已經過去了。贏家是那些懂得退一步、刪除舊的死板指令，轉而在模型周圍建立最乾淨、最穩健的迴圈與外圍框架的工程師。在 Fable 5 的時代，刪除舊指令才是真正的最佳化。說得太好了。

**[19:37]** 而且指南在第一章最後，其實留下了一個非常有意思的進階應用。喔，是什麼？當你的基礎迴圈——也就是包含了記憶、邊界、驗證器這些東西——成功運作之後，你可以再加上一個主管代理（supervisor agent）。主管代理？對。想像一個子系統，它會在計時器響起時自動喚醒，比對當前的進度跟最初的目標，然後發出修正方向的指令。這徹底彌合了「它在你睡覺時工作」和「你真正信任它在你睡覺時工作」這兩者之間的巨大鴻溝。

**[20:08]** 哇，想像一下，當你的 Harness 完善到這種程度——包含了記憶、邊界防護、全新上下文的驗證器，甚至還有一個會定時醒來巡視的主管代理——這時候，究竟是那個名叫 Fable 5 的模型是這個系統的大腦，還是你親手打造的這個外圍框架本身，才是這個系統真正的智慧所在？這是個非常值得深思的問題。對啊。當強大的底層模型變成了一種可以隨時抽換、隨插即用的標準化引擎，你的 Harness 才是你真正帶得走、最無可取代的核心資產。這個問題就留給你慢慢思考了。感謝你參與今天的專屬知識解析，我們下次見。我們下次見。
