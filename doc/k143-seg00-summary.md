## 一句話結論

新模型的槓桿已經從「把提示詞寫得精巧」移到「圍繞模型搭 Harness」：給目標、原因與限制條件，加上記憶、全新上下文的驗證器、五個提示詞模組和正確的 API 設定（備援、effort），模型自己補上做法；底層模型可以抽換，Harness 才是帶得走的資產 [00:58][04:10][20:33]。

## 重點（10 點）

1. **大反學習**：22 步編號指令、全大寫的「一步一步思考」、長檢查表，過去是柺杖，現在是累贅。Fable 5 會忠實地照做錯誤或多餘的步驟，反而失去自己繞過陷阱的能力 [01:46][02:01][03:03]。
2. **用「目標、原因、限制條件」取代步驟清單**：模型知道「為什麼」，就能替你做那些沒指定的小決策，例如重構時在兩個等價解法中選省記憶體的那個 [04:10][04:30]。
3. **Fable 5 與 Mythos 5 是同一能力、同一價格的雙胞胎**：輸入每百萬 token 10 美元、輸出 50 美元，1M 上下文、單次最多 128k 輸出；差別只在部署與安全邊界 [05:24][06:19]。
4. **Mythos 5 不是更聰明的超級大腦**：它是 Project Glasswing 受限部署、拿掉部分分類器的版本。分類器拿掉之後，你的 Harness（範圍閘門、驗證器、人工批准路徑）就是唯一的護城河 [06:46][07:27]。
5. **備援（fallback）不是自動也不是免費**：API 端必須主動傳 fallback 參數；沒加的話，遇到拒答請求就停在那裡。已生成的 token 照樣收費，Opus 4.8 接手也照 4.8 費率計價。要寫處理拒答與備援的防禦性程式碼 [08:22][09:36]。書中補充：拒答是 HTTP 200＋`stop_reason: "refusal"`，要先看 stop_reason 再讀內容（`code/fable5/README.md` API 注意事項第 3、4 條）。
6. **「Claudish 秘密語言」是神話**：那只是模型在長對話裡為了省 token 寫出的箭頭縮寫，用一段白話摘要提示詞就能修正 [10:12][10:57]。
7. **Harness 支柱一：檔案式記憶**：一課一個 Markdown 檔、第一行是摘要、外加一個總索引檔；不要把幾萬字的對話紀錄整包塞給模型 [11:48]。
8. **Harness 支柱二：全新上下文的驗證器**：做的人不當審的人。驗證器是獨立的子代理，只看最終宣告和原始證據（測試日誌、編譯錯誤），不看執行者的推論過程，才能防止捏造進度 [12:24][12:46][13:14]。
9. **五個第一天就能貼的提示詞模組**：邊界（先提案、不可逆動作要批准）、接地進度（每個宣告綁定產出物）、自主性（小決定自己做、不要事事停下來問）、白話摘要（完整句子、不用箭頭縮寫）、上下文平靜（不要因為怕空間不夠就刪減工作）[14:02]～[15:26]。
10. **API 地雷與 effort 旋鈕**：思考永遠開著，試圖關閉回 400；temperature、top_p 被拒絕；組織設零資料保留會回 400（逐字稿說要求 30 天保留）。effort 分 low／medium／high／xhigh／max，預設 high；日常任務用 low／medium 在 Fable 5 上常勝過舊模型開到最大，要依 Harness 各環節難易動態設定 [16:13][16:57][17:18][18:45]。

### 1. 角色定義：主管代理在 Harness 裡的位置

- **它是加在已經跑穩的基礎迴圈之上的一層**，不是第一天就要有的東西。前提是記憶、邊界、驗證器都已經成功運作 [19:43]。（逐字稿）
- **它是一個獨立子系統，按時間觸發**（計時器響起時醒來），不是一直盯著執行者 [19:52]。（逐字稿）
- **它的工作對象是「方向」**：拿目前進度去對最初目標，偏了就下修正指令 [19:56]。（逐字稿）
- **它和驗證器的分工不同**：驗證器回答「這一件事真的做完了嗎」（只看宣告與證據，回 PASS/FAIL）[13:14]；主管代理回答「整體還朝著原本目標前進嗎」[19:56]。（逐字稿兩處對照；分工的說法是推導）
- **書中與它最接近的結構**：

### 4. 與執行者、驗證者的分工與資料流

```text
人類
 │ 給：目標（可檢查）、原因、限制條件／邊界、停止條件、預算
 ▼
主管代理（定時喚醒；高 effort，判斷密集）
 │ ① 讀 memory/INDEX.md（只讀索引，需要時才開單一教訓檔）
 │ ② 拆解 → 交接單（目標、輸入、完成定義、限制、輸出位置）
 ▼
執行者（便宜模型或 medium effort；只在交接單範圍內動手）
 │ 產出物：diff、測試輸出、檔案
 ▼
驗證者（全新上下文、low effort；只收「規格＋產出物」，不收執行者敘述）
 │ 回：PASS／FAIL＋一句理由
 ▼
主管代理
 │ ③ PASS → 寫入記憶（一課一檔、有出處）；FAIL → 計數、修正方向
 │ ④ 比對進度與最初目標 → 發修正指令或繼續下一輪
 │ ⑤ 檢查停止條件：達標／同一失敗 3 次／預算用完／拒答 → 停並回報
 ▼
人類 ← 白話回報（結果一句話＋有證據的完成項＋失敗與未驗證項＋需要你決定的一件事）
```

- 資料流的兩條硬規則：**驗證者不看執行者的敘述**、**記憶只收驗證通過的結果**（逐字稿 [13:14]；書中 `agentic_soc/triage_loop.py:67–76、98–100`）。
- effort 配置（規劃 xhigh／執行 medium／評分 low）取自 `code/fable5/README.md` API 注意事項第 2 條；主管代理用高 effort 是推導（它做的是 plan_or_audit 那種判斷工作）。
- 圖中「定時喚醒」「比對目標」「修正指令」來自逐字稿 [19:48]～[19:58]；其餘箭頭是把書中迴圈六零件（觸發、規則、執行者、驗證者、記憶、停止條件，見 prompts/ch02.md）組起來的推導。
